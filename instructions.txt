第一章  功能介绍
================================================================================

【一句话简介】
  一个可以同时监控「抖音」和「哔哩哔哩」主播直播状态，并在主播开播的瞬间自动
  触发录播、下播后自动转码为 MP4、并通过微信推送提醒你的 Windows 桌面程序。

【核心功能】

1. 多主播直播状态监控
   - 同时支持抖音（Douyin）和哔哩哔哩（Bilibili）两大平台。
   - 可添加任意数量主播（自动化任务上限 20 个）。
   - 每个主播可单独「启用 / 禁用」监控，互不影响。
   - 表格中实时显示：主播名称、平台、ID/URL、所属通知组、直播状态、
     上次监控时间、监控启用状态。
   - 「上次监控时间」开始不断跳动，即表示监控已生效。

2. 开播 / 下播微信推送通知
   - WxPusher 通知：绑定微信，实时接收开播、下播提醒。
   - 企业微信机器人通知：通过群机器人 Webhook 推送到企业微信群。
   - 通知组机制：可以把主播分组，为每个组单独指定使用哪种通知方式。
   - 开播消息模板示例：
       标题：开播提醒：{主播名} 在{平台}开播了!
       正文：你关注的{主播名}在{平台}开播啦!
             主播名称: xxx
             直播平台: 抖音 / 哔哩哔哩
             主播ID: xxx
             开播时间: 2026-09-18 09:18:31
   - 下播消息模板示例：
       标题：下播提醒：{主播名} 在{平台}结束直播了!
   - 支持「勿扰时段」，该时段内所有通知被静默屏蔽（监控与录播照常运行）。

3. 自动录播（两大引擎）
   - V1（传统录播，基于 aria2 RPC）：
       通过 aria2 下载引擎抓取直播流，任务以「任务列表」形式管理，
       支持暂停 / 继续 / 停止并移除，支持手动添加录播任务。
   - V2（抖音专用录播，推荐）：
       内置在程序内的抖音录播面板，一行一个主播，可直接在表格里切换
       「自动录播」「画质」「启停」「切片」「详情/编辑」，
       录制中实时显示已录时长、速度、大小、分辨率、帧率、码率。
   - V2 支持「切片」：点击切片按钮会暂停 0.5 秒后自动继续，用于把
       一段长直播切成多个文件。

4. 五种录播画质 + 极致画质
   - 原画（or4 / origin）—— 最高画质，需要 cookie.txt
   - 蓝光（uhd）—— 需要 cookie_uhd.txt
   - 超清（hd）—— 需要 cookie_hd.txt
   - 高清（ld）—— 需要 cookie_ld.txt
   - 标清（sd）—— 需要 cookie_sd.txt
   - 极致（max）—— 蓝V连麦专用，优先级高于原画（仅脚本生成器可选）
   - 每个主播可单独设置画质，程序会自动调用对应的 Cookie 文件。

5. 断流自动重连 / 完整性保护
   - 录播脚本内置「优先保证录播完整性」开关：
       勾选后接受所有画质链接，画质掉档也不中断，最大程度保证完整；
       不勾选则严格只接受目标画质，画质不符时放弃该链接。
   - 内置速度监控：当速度低于阈值且长时间无画质提升时，自动重试。
   - 自动续录：程序重启 30 秒后会自动检查「正在直播且启用录播但 aria2
     中无任务」的主播，并自动恢复录播。

6. 下播后自动转码（FLV → MP4）
   - 每主播可独立设置是否自动转码、是否保留 FLV 源文件。
   - 转码采用 ffmpeg 无损封装（-c copy），速度极快，不重新编码，不损画质。
   - 可自定义转码输出目录（默认 %APP_DIR%\已转码\{主播名}）。
   - 转码脚本为「自动转码-{主播名}.bat」，由程序自动生成。

7. 自动化任务（触发式执行脚本）
   - 可把任意 .py / .bat 脚本绑定到某个主播的某个触发条件上。
   - 触发条件仅两个：「直播中」和「未开播」。
   - 例如：开播 → 执行「开始录播-XX.py」；下播 → 执行「自动转码-XX.bat」。
   - 支持「自启动」开关、手动测试执行、强行停止。

8. 勿扰 / 休眠 / 定时调速
   - 勿扰时段：屏蔽通知，但不影响监控和录播。
   - 休眠时段：暂停监控（录播不停止），用于夜间休息。
   - 定时调速：指定时间段自动切换监控速度档位。

9. 监控速度五档调节
   - 1 档（原始速度）→ 5 档（最慢），主播越多、机器越弱可调高档位省资源。

10. 日志系统
   - 支持按天分割日志文件（monitor-YYYY-MM-DD.log），默认存放在
     程序目录的 logs 文件夹下。
   - 界面内可清空日志、导出日志、直接打开日志文件。

11. 内置向导
   - 主播监控向导（4 步）、传统录播任务向导（5 步），全程引导式配置。

12. 用户环境变量检测
   - 一键检测 Python / ffmpeg / aria2c / msedgedriver 是否在 PATH 中，
     并提供修复指引。

13. 自定义通知组
   - 可建立多个通知组，将不同主播归入不同组，为不同组设置不同通知渠道。

第二章  第一次使用的准备工作
================================================================================

使用本程序前，请按顺序完成以下 5 项准备工作。全部为一次性工作，配置完成后
以后直接双击运行即可。


--------------------------------------------------------------------------------
2.1  安装 Python 环境
--------------------------------------------------------------------------------

1) 下载 Python（推荐 3.8 及以上，实测 3.13 可正常使用）：
   官网：https://www.python.org/downloads/
   国内如访问慢，可用华为云镜像：
   https://mirrors.huaweicloud.com/python/

2) 安装时【务必勾选】「Add Python to PATH」（添加到 PATH），
   然后点击「Install Now」。

3) 安装完成后验证：
   按 Win + R，输入 cmd 回车，在命令行中输入：
       python --version
   若显示类似「Python 3.13.x」即安装成功。
   若提示「不是内部或外部命令」，说明 PATH 未生效：
       重新安装并勾选 Add Python to PATH，或手动把 Python 安装目录及
       Python安装目录\Scripts 添加到系统环境变量 Path 中。

4) 建议同时升级 pip：
       python -m pip install --upgrade pip


--------------------------------------------------------------------------------
2.2  使用 requirement.txt 补充 Python 依赖
--------------------------------------------------------------------------------

程序依赖清单就在程序目录下的 requirement.txt，内容为四行：

    requests
    selenium
    aria2p
    psutil

【方法一：在线一键安装（推荐）】

如果你所在网络访问国外源很慢，建议先切换为国内镜像源，
在 cmd 中执行（任选其一）：

  阿里云镜像：
    pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/
    pip config set install.trusted-host mirrors.aliyun.com

  清华大学镜像：
    pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
    pip config set install.trusted-host pypi.tuna.tsinghua.edu.cn

  然后安装依赖（两种方式任选）：
   方式 A：逐个安装
       pip install requests
       pip install selenium
       pip install aria2p
       pip install psutil

   方式 B：直接读取 requirement.txt 一次性安装
       先 cd 到程序目录：
           cd /d "程序所在目录的完整路径"
       然后执行：
           pip install -r requirement.txt

   如果部分包安装缓慢，可临时指定镜像：
       pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirement.txt

【方法二：离线安装（网络极度受限时）】

1) 在一台能联网的电脑上，下载上述四个包及其全部依赖的 .whl 文件：
       pip download -d ./pkgs -r requirement.txt
2) 把 pkgs 文件夹拷到目标电脑，在 pkgs 目录下执行：
       pip install --no-index --find-links=./pkgs -r requirement.txt

【验证依赖是否装好】

在 cmd 中依次执行：
    python -c "import requests; print('requests OK')"
    python -c "import selenium; print('selenium OK')"
    python -c "import aria2p; print('aria2p OK')"
    python -c "import psutil; print('psutil OK')"
全部输出 OK 即安装完成。

【重要提示】
- selenium 用于抖音监控（Selenium 驱动 Edge 浏览器采集 Cookie）。
- aria2p 用于 V1 传统录播（与 aria2 RPC 通信）。未安装时，
  「正在录播(V1)」标签页会出现红字警告：
      「警告: 未安装aria2p库，请使用 'pip install aria2p' 安装」
- requests 用于调用抖音 / B站接口和推送通知。
- psutil 用于进程检测（转码脚本判断 aria2 是否有活跃任务）。
- 本程序使用 Python 标准库 tkinter 构建界面，Windows 官方 Python 安装包
  默认自带 tkinter，无需额外安装。


--------------------------------------------------------------------------------
2.3  准备 aria2 与 ffmpeg
--------------------------------------------------------------------------------

本程序目录中已自带以下文件，无需另外下载：

  aria2c.exe            —— aria2 下载引擎主程序
  aria2.bat             —— 启动 aria2 的批处理（启用 RPC、监听 6800 端口）
  aria2.vbs             —— 无窗口方式后台启动 aria2
  aria2setting.html     —— aria2 的 WebUI 设置页面（由「aria2设置」按钮打开）
  ffmpeg.exe            —— 视频转码工具（FLV → MP4 无损封装）

aria2.bat 的实际启动参数为：
  aria2c --enable-rpc --rpc-listen-all --disable-ipv6=true
         --max-concurrent-downloads=100 --max-connection-per-file 16
         --timeout=120 --dir=<当前脚本所在目录>

【说明】
- aria2 是录播的核心下载引擎，程序通过 RPC 接口（默认 127.0.0.1:6800）
  与之通信。程序内「启动Aria2」按钮会自动调用上述脚本启动它。
- ffmpeg 仅在「下播后自动转码」时使用，把 FLV 无损封装成 MP4。
- 若使用 Win7 / Win8，程序首次运行会自动把 aria2c.exe 和 aria2.bat
  复制到程序目录，并使用「local_bat」方式启动（详见 3.4 节）。


--------------------------------------------------------------------------------
2.4  准备 Edge 浏览器与 msedgedriver.exe
--------------------------------------------------------------------------------

抖音的监控与 Cookie 采集需要 Selenium 驱动 Microsoft Edge 浏览器，
因此需要与你的 Edge 浏览器版本【完全匹配】的 msedgedriver.exe。

【第一步：查看你的 Edge 版本】
  打开 Edge → 地址栏输入 edge://version/ 回车 →
  记下「版本」号前四段，例如 150.0.4078.48。

【第二步：下载对应版本的 msedgedriver.exe】
  方法一（推荐，镜像站，速度快、版本全）：
    浏览器访问：
      https://registry.npmmirror.com/binary.html?path=edgedriver/
    或直接按版本拼接下载地址：
      https://cdn.npmmirror.com/binaries/edgedriver/150.0.4078.48/edgedriver_win64.zip
    （把版本号替换成你自己的 Edge 版本）

  方法二（微软官方）：
    按以下格式拼接地址并访问：
      https://msedgedriver.microsoft.com/109.0.1518.78/edgedriver_win64.zip
    （把 109.0.1518.78 替换成你自己的 Edge 版本）

  压缩包类型说明（按你的系统选择）：
      edgedriver_win64.zip       —— 64 位 Windows（绝大多数电脑选这个）
      edgedriver_win32.zip       —— 32 位 Windows
      edgedriver_arm64.zip       —— ARM64 架构 Windows
      edgedriver_linux64.zip     —— Linux 64 位
      edgedriver_mac64.zip       —— Intel Mac
      edgedriver_mac64_m1.zip    —— Apple M1 Mac

【第三步：放置文件】
  解压出里面的 msedgedriver.exe，放到【与主程序同一文件夹】下，
  即程序目录下应存在：
      ...\程序目录\msedgedriver.exe

【自动下载机制（好消息）】
  程序启动时会自动检查 EdgeDriver 是否与当前 Edge 版本匹配：
  - 程序优先读取注册表 HKCU\Software\Microsoft\Edge\BLBeacon 的 version 值
    获取 Edge 版本。
  - 若版本不匹配，会自动备份旧文件为 .bak 并尝试下载对应版本
    （先走 npmmirror 镜像，失败再走微软官方源）。
  - 若自动下载失败，可打开「高级设置 → 用户环境变量检测」页面手动恢复备份。
  因此，即使你不手动下载，程序多数情况下也能自行完成适配。


--------------------------------------------------------------------------------
2.5  将程序目录加入系统 PATH（可选但推荐）
--------------------------------------------------------------------------------

为了让程序内调用的 ffmpeg.exe、aria2c.exe、msedgedriver.exe 以及
python 命令在任何位置都能被找到，建议把程序所在文件夹加入系统 PATH：

  方法一（图形界面）：
    1) Win + R → 输入 sysdm.cpl 回车
    2) 「高级」选项卡 → 「环境变量」
    3) 在「用户变量」或「系统变量」中选中 Path → 「编辑」→ 「新建」
    4) 粘贴程序目录完整路径 → 确定 → 确定
    5) 【重要】重新打开 cmd / 重启程序使 PATH 生效

  方法二（程序内置检测）：
    打开程序 → 「高级设置」标签页 → 「用户环境变量检测」按钮，
    该窗口含三个子标签页：
        · 用户变量 PATH 检测与修复
        · 系统变量 PATH 检测与修复
        · 帮助说明
    可一键检测 Python、ffmpeg、aria2c、msedgedriver 是否已被正确识别。

  注意：如果你直接使用打包好的 exe 版本运行，可跳过 2.1 与 2.2，
        但 2.3 / 2.4 中的引擎文件仍需与 exe 放在同一目录。

--------------------------------------------------------------------------------
3.3  自动初始化流程说明
--------------------------------------------------------------------------------

程序启动后会自动依次完成以下工作（无需人工干预）：

  1) 读取配置文件 streamer_monitor_config.json（不存在则创建默认配置）。
  2) 检测系统版本并初始化 aria2 运行方式（仅首次，见 3.4 节）。
  3) 后台线程初始化：加载配置 + 初始化 EdgeDriver（版本检测/自动下载）。
  4) 延迟启动（delayed_startup）：
       · 自动启动直播监控线程
       · 若已勾选「启用aria2自动启动和连接」，则自动启动 aria2 并连接
       · 约 1 秒后：按「启动时自动获取方式」设置自动获取抖音监控 Cookie
       · 约 2 秒后：自愈修复过期的画质元信息缓存（quality_meta）
       · 约 30 秒后：自动续录检查（恢复意外中断的录播任务）

【首次启动时的界面表现】
  程序会自动弹出一个 Edge 浏览器窗口，打开抖音「封茗囧菌」的个人主页，
  用于采集【未登录状态】的 Cookie 以监控直播状态。
  如无图形验证码等阻碍，等待约 15 秒左右即可自动完成并关闭窗口。
  这属于正常现象，不是程序出错。


--------------------------------------------------------------------------------
3.4  aria2 运行方式自动识别
--------------------------------------------------------------------------------

程序在首次运行时，会根据 Windows 版本自动决定 aria2 的启动方式，
并把结果写入配置文件（之后不再重复检测）：

  · Windows 10 / 11（主版本号 = 10）
      → aria2_run_mode = "normal"（正常方式启动）

  · Windows 7 / 8（主版本号 < 10）
      → aria2_run_mode = "local_bat"
        并自动将 aria2c.exe 与 aria2.bat 复制到程序目录，
        以本地批处理方式启动，兼容旧系统。

配置文件中会记录以下三个字段：
    "aria2_mode_initialized": true       表示已完成初始化
    "aria2_run_mode": "normal"           当前运行方式
    "detected_windows_major": 10         检测到的系统主版本号

如需重新检测，删除这三个字段后重启程序即可。

第六章  标签页详解之二：通知设置

本页包含三块配置：WxPusher、企业微信机器人、抖音 Cookie。

--------------------------------------------------------------------------------
6.1  WxPusher 配置
--------------------------------------------------------------------------------

  【启用WxPusher通知】复选框
      默认：☑ 勾选（启用）。
      取消勾选后，所有 WxPusher 通知停止发送（通知组内的勾选也会被覆盖）。

  【AppToken】
      WxPusher 应用的 AppToken。
      获取：访问 https://wxpusher.zjiecode.com/ 注册并创建应用，
            在应用详情中复制 AppToken。

  【用户UID】
      接收消息的微信用户 UID。
      获取：关注 WxPusher 公众号 → 在「我的」中查看 UID（形如 UID_xxxxx）。

  【测试通知】按钮
      立即发送一条测试消息，用于验证 AppToken / UID 是否配置正确。

  页面下方还有「还没有WxPusher账号? 点击这里注册」的蓝色链接，
  点击会用默认浏览器打开注册页。

--------------------------------------------------------------------------------
6.2  企业微信机器人配置
--------------------------------------------------------------------------------

  【启用企业微信机器人通知】复选框
      默认：☐ 未勾选（禁用）。

  【Webhook URL】
      企业微信群机器人的 Webhook 地址，形如：
      https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx
      获取：企业微信群 → 右上角设置 → 群机器人 → 添加机器人 → 复制 Webhook。

  【测试通知】按钮
      发送一条测试消息到企业微信群。

  说明：企业微信通知以 text 类型发送，消息内容为「标题 + 空行 + 正文」。

--------------------------------------------------------------------------------
6.3  抖音 Cookie 设置
--------------------------------------------------------------------------------

  【启动时自动获取方式】下拉框，三个选项：
      · 不自动获取
            启动时不采集 Cookie，完全依赖已有的 cookie 文件。
      · 不登录获得Cookie   （默认值）
            启动时自动打开 Edge 访问抖音主页，采集【未登录】Cookie，
            适合普通家用电脑，无需扫码。
      · 登录获得Cookie
            启动时复用 douyinliveck.txt 中的历史登录态（需该文件存在）。
            【重要】只有工作目录下存在 douyinliveck.txt 时才可用；
            界面上会显示提示，绿色文字「（已检测到）」表示可用，
            红色文字「（未检测到，此选项不可用）」表示不可用。

  【当前 Cookie】文本框
      只读，显示当前用于监控的抖音 Cookie 内容（便于确认是否已获取）。

  【刷新监控Cookie】按钮
      重新采集用于监控直播状态的 Cookie，弹出「选择刷新监控Cookie的方式」
      对话框，提供三种方法：
        方法一（家用电脑）：不登录获得 Cookie —— 程序自动采集
        方法二（服务器）：登录并获得 Cookie —— 打开登录窗口扫码登录
        方法三：手动填写 Cookie —— 手动粘贴
      当「直播间正在直播但监控状态不正确」时使用。

  【刷新录播Cookie】按钮
      打开「抖音Cookie刷新器」窗口（详见第十六章 16.3），
      用于生成 cookie.txt 及四个画质 Cookie 文件。
      当「直播间明明在直播但拿不到直链」时使用。

--------------------------------------------------------------------------------
6.4  页面底部使用说明（原文）
--------------------------------------------------------------------------------

  使用说明：
  1. 访问 wxpusher.zjiecode.com 注册获取AppToken
  2. 在WxPusher中绑定微信获取用户UID
  3. 添加要监控的主播
  4. 点击'开始监控'启动服务
  哔哩哔哩：需要提供主播UID（个人空间链接中的数字），主播名称和直播间ID将自动获取
  抖音：需要提供主播主页URL（完整URL）

另外，处于「勿扰时段」时，所有通知会被完全屏蔽（见 12.3）。

        原画 / 蓝光 / 超清 / 高清 / 标清
      不同画质对应不同的 Cookie 文件与清晰度（见第十七章）。

  【可编辑项】
      主播名称         文本输入
      抖音号           文本输入
      录制画质         下拉框（原画 / 蓝光 / 超清 / 高清 / 标清），默认「原画」
      自动录播         复选框

  【只读实时信息】
      直播状态、录播状态、已录制时长、录制速度、录制文件大小、

      （数据每 2 秒自动同步一次）

--------------------------------------------------------------------------------
9.3  V2 自动录播的工作流程
--------------------------------------------------------------------------------

  1) 直播状态监控线程检测到主播「未开播 → 直播中」。
  2) 若该主播「自动录播」为 ✓，则立即解析直播流地址（按设定的画质）。
  3) 通过 aria2 建立下载任务，文件保存到程序目录，命名格式：
          {主播名}-{YYYYMMDD-HHMMSS}-抖音-{主播名}_{画质后缀}.flv
     例如：Xlin（无畏契约手游）-20260918-083537-抖音-Xlin（无畏契约手游）_or4.flv
  4) 录制中实时刷新已录时长、速度、大小、分辨率、帧率、码率。
  5) 主播下播后，若开启自动转码，则约 30 秒后自动执行
     「自动转码-{主播名}.bat」把 FLV 转为 MP4（见第十八章）。

11.4  触发机制说明
--------------------------------------------------------------------------------

  · 只有「自启动」为开启状态的任务才会被自动触发。
  · 触发时会同时匹配【主播名称 + 触发条件 + 平台】，
    因此 B站和抖音的同名主播不会互相误触发。
  · 防重复触发：如果该任务已在运行中或已在启动队列中，则跳过本次触发，
    避免同一任务被重复执行。
  · 程序重启 30 秒后会自动检查并恢复异常中断的录播任务。

第十二章  标签页详解之八：高级设置
================================================================================

页面顶部说明文字：
    「慢速查询直播状态档位（1档为原始速度，档位越高，查询间隔越长、越省资源）。」

--------------------------------------------------------------------------------
12.1  监控速度档位
--------------------------------------------------------------------------------

  【请选择监控速度档位】单选按钮组，共 5 档：

      档位   界面文字             倍率    适用场景
      ----  ------------------  ------  --------------------------------
      1     1档（原始速度）      1.0     主播少、机器性能好（默认）
      2     2档（稍慢）          1.5     主播较多
      3     3档（中等慢）        2.0     主播很多
      4     4档（较慢）          3.0     主播非常多、机器较弱
      5     5档（最慢）          4.0     极限省资源、长时间挂机

  倍率作用：
      · 单个主播之间的查询间隔 every_sleep = 基准值 × 倍率
        基准值 = max(3.5, 4 + 0.5 × min(主播数, 10))  秒
      · 每轮全部检查完后的额外休眠 total_cycle = (max(5.0, 主播数×3.0) × 倍率) ÷ 2  秒

  切换档位会立即刷新下方的预览文字；档位修改后需要点击【保存配置】持久化。

  【当前启用监控的主播数量】标签
      显示当前启用监控的主播数量，作为时间估算的依据。

  【各档位实际时间说明（仅供参考，估算的时间不准确）】区域
      实时预估并显示当前档位下每个主播的查询间隔与整轮休眠时长。

--------------------------------------------------------------------------------
12.2  高级功能设置（三个按钮）
--------------------------------------------------------------------------------

  【勿扰/休眠时段设置】
      打开「勿扰 / 休眠时段设置」窗口（约 700x550，含 2 个子标签页）：

      · 勿扰时段（do_not_disturb_periods）
          格式：[{"start": "HH:MM", "end": "HH:MM"}, ...]
          作用：该时段内【屏蔽所有通知】（开播/下播提醒都不会发送），
                但监控与录播正常运行。
          典型用途：夜间不希望被推送吵醒。

      · 休眠时段（sleep_periods）
          格式同上。
          作用：该时段内【暂停监控】（不检查直播状态），
                但已经在进行的录播不会停止。
          典型用途：凌晨时段休息，减少请求。

  【定时调速设置】
      打开「定时调速设置」窗口（约 700x550）。
      格式：[{"start": "HH:MM", "end": "HH:MM", "level": 1~5}, ...]
      作用：在指定时间段内自动切换到指定的监控速度档位；
            不在任何时段内时使用「高级设置」页选择的默认档位。
      典型用途：白天 1 档快速响应，深夜 5 档省资源。

  【用户环境变量检测】
      打开「用户环境变量检测」窗口（约 800x600，含 3 个子标签页）：
        · 用户变量 PATH 检测与修复
        · 系统变量 PATH 检测与修复
        · 帮助说明
      用于检测 Python、ffmpeg、aria2c、msedgedriver 是否已被系统正确识别，
      并在 EdgeDriver 自动下载失败时恢复备份文件。

================================================================================
第十六章  Cookie 体系详解（核心）
================================================================================

Cookie 是本程序能否正常监控与录播的关键。程序使用两套独立的 Cookie：

    ① 监控 Cookie   —— 用于查询「主播是否在直播」
    ② 录播 Cookie   —— 用于获取直播流直链（分 5 种画质）

--------------------------------------------------------------------------------
16.1  监控 Cookie
--------------------------------------------------------------------------------

  存储位置：配置文件的 "douyin_cookie" 字段（字符串），
            以及历史登录态文件 douyinliveck.txt（JSON 格式）。

  采集原理：Selenium 驱动 Edge 打开抖音页面，采集浏览器 Cookie。

  三种获取方式（在「通知设置 → 抖音 Cookie 设置」中选择）：

    ① 不自动获取
         完全不采集，使用已有 Cookie。适用于服务器长期运行场景。

    ② 不登录获得Cookie（默认）
         启动时自动打开 Edge 访问抖音个人主页，采集未登录状态 Cookie。
         无需扫码，等待约 15 秒。
         注意：未登录 Cookie 有时效性，失效后需重新获取。

    ③ 登录获得Cookie
         复用 douyinliveck.txt 中的历史登录态（包含登录后的完整 Cookie）。
         需要该文件存在（界面会给出绿/红提示）。
         适用于「服务器 + 长期稳定」场景。

  【何时需要刷新监控 Cookie】
      直播间明明在直播，但程序显示「未开播」时。

  【刷新入口】
      通知设置页 →【刷新监控Cookie】按钮 → 三选一的方式对话框：
          方法一（家用电脑）：不登录获得Cookie
          方法二（服务器）：登录并获得Cookie（打开登录窗口扫码）
          方法三：手动填写Cookie

--------------------------------------------------------------------------------
16.2  录播 Cookie
--------------------------------------------------------------------------------

  存储位置：程序目录下的 5 个 txt 文件：

      cookie.txt          → 原画（or4 / origin）
      cookie_uhd.txt      → 蓝光（uhd）
      cookie_hd.txt       → 超清（hd）
      cookie_ld.txt       → 高清（ld）
      cookie_sd.txt       → 标清（sd）

  读取规则（程序自动处理）：
      · 录制某画质时，读取对应画质的 Cookie 文件；
      · 如果该文件不存在或为空，则自动回退使用 cookie.txt（原画）。
      因此只要 cookie.txt 有效，最基本的录播就能进行。

  【何时需要刷新录播 Cookie】
      直播间正在直播，但程序无法获得直播流直链（录播启动失败）时。

--------------------------------------------------------------------------------
16.3  抖音 Cookie 刷新器（录播 Cookie 生成器）
--------------------------------------------------------------------------------

  打开方式：通知设置页 →【刷新录播Cookie】按钮。
  窗口标题：「抖音Cookie刷新器」，尺寸约 500x520。

  使用步骤：
      1) 用 Edge 浏览器打开一个【正在直播中】的抖音直播间页面，
         地址形如 https://live.douyin.com/1234567890
      2) 点击刷新按钮，程序开始倒计时（默认 28 秒，可在 20~300 秒间调整）。
      3) 程序会自动查找地址形如 live.douyin.com/数字 的标签页，
         从中采集 Cookie。
      4) 采集完成后自动写盘：
            · 为 origin（原画）写入 cookie.txt
            · 分别为 uhd / hd / ld / sd 写入 4 个画质 Cookie 文件
            · 同时把完整 cookies 写入 douyinliveck.txt（供登录方式复用）

  【重要补充】
      采集到的 cookie.txt 建议手动增补以下两条内容，以获得原画直链：

          webcast_local_quality=origin;live_local_quality=origin

      （原 ReadMe 说明书的要求：加入这两项后录制 cookie 才算准备完毕。）

第十八章  自动转码功能详解
================================================================================

--------------------------------------------------------------------------------
18.1  功能说明
--------------------------------------------------------------------------------

  抖音直播流录制下来是 FLV 格式。本程序可配置在【主播下播后】自动把 FLV
  转码为 MP4，方便后期播放与剪辑。

  转码采用 ffmpeg 的无损封装模式：
      ffmpeg.exe -i "输入.flv" -c copy "输出.mp4" -y
  · -c copy 表示不重新编码，只做容器封装，速度极快且画质零损失。
  · -y 表示覆盖同名文件时不询问。

--------------------------------------------------------------------------------
18.2  配置入口
--------------------------------------------------------------------------------

  入口一：「抖音录播(V2)」→「详情/编辑」→「下播后自动转码设置」
      【下播后自动转码（FLV→MP4）】      复选框，默认 ☑
      【转码后保留FLV源文件（不勾选则删除）】 复选框，默认 ☐
      【转码后保存位置】                  输入框
          默认：%APP_DIR%\已转码\{主播名}
          %APP_DIR% 表示程序所在目录，{主播名} 会自动替换。

  入口二：「录播脚本生成器」
      【录播完毕后自动转码】          复选框，默认 ☐
      【转码完成后不保留原文件】      复选框，默认 ☐（需先勾选上一项才可用）

--------------------------------------------------------------------------------
18.3  转码脚本（自动转码-{主播名}.bat）
--------------------------------------------------------------------------------

  程序会为每个主播自动生成一个转码脚本，文件名为
      「自动转码-{主播名}.bat」

  主要内置参数：
      SIZE_TOLERANCE_MB = 25     转码前后文件大小可接受的误差（MB）
      TARGET_DIR        = %APP_DIR%\已转码\{主播名}
      LOG_FILE          = %TARGET_DIR%\converted_files.txt
      ffmpeg 命令       = ffmpeg.exe -i "in.flv" -c copy "out.mp4" -y
      启动延迟          = ping -n 30 127.0.0.1（约 30 秒，
                          等待录播任务彻底结束后再开始转码）

  【不保留原文件模板的额外保护】
      删除 FLV 前会通过 PowerShell 检查 aria2 中是否还有该主播的
      active（活动）任务：
          · 有  → 跳过删除，保留文件，避免误删正在写入的文件
          · 无  → 确认转码成功后再删除 FLV

  【转码记录】
      每次转码的结果会追加记录到 TARGET_DIR\converted_files.txt，
      便于核对哪些文件已转码。

--------------------------------------------------------------------------------
18.4  转码任务如何被触发
--------------------------------------------------------------------------------

  程序添加抖音主播时会自动为其生成转码 bat，并注册一条自动化任务：
      主播 = 该主播
      触发条件 = 未开播
      脚本 = 自动转码-{主播名}.bat
      自启动 = 开启

  因此主播一开播、下播后该脚本就会自动执行，无需人工干预。

  你也可以在「自动化任务」标签页手动查看、修改或删除这些任务。

第二十章  常见问题与故障排查（FAQ）
================================================================================

Q1. 程序启动后自动弹出一个抖音窗口，是中毒了吗？
A1. 不是。这是正常的监控 Cookie 采集流程：程序用 Selenium 打开抖音个人
    主页，采集未登录 Cookie 用于查询直播状态，约 15 秒后自动关闭。
    如果不想每次启动都采集，可把「启动时自动获取方式」改为「不自动获取」。

Q2. 提示「配置文件 streamer_monitor_config.json 不存在」或「格式错误」。
A2. ① 若不存在：确认程序目录有写权限（不要放在 C:\Program Files 等
       需要管理员权限的目录），重启程序会自动生成默认配置。
    ② 若格式错误：配置文件被手工改坏了。用记事本打开检查 JSON 格式
       （注意逗号、引号、括号配对），或删除该文件让程序重建
       （注意：删除会丢失所有主播和设置，请先备份）。

Q3. 「正在录播(V1)」页出现红字「未安装aria2p库」。
A3. 执行 pip install aria2p 安装即可。若已安装仍报错，可能是安装到了
    其它 Python 版本下，请用 python -m pip install aria2p 指定当前解释器。

Q4. 「开始监控」后「上次监控时间」一直不变化。
A4. ① 确认主播的「监控状态」为「启用」（可用【启用/禁用自动监控】切换）。
    ② 确认已点击【开始监控】。
    ③ 若提示缺少 selenium，请 pip install selenium。
    ④ 检查网络能否访问抖音 / B站。
    ⑤ 抖音监控依赖 Edge 与 msedgedriver，版本不匹配会导致失败，
       请参考 2.4 节更新驱动。

Q5. 直播间明明在直播，程序却显示「未开播」。
A5. 监控 Cookie 失效。请点击【刷新监控Cookie】，选择合适的方式重新获取。
    服务器环境建议使用「登录获得Cookie」并保证 douyinliveck.txt 存在。

Q6. 直播间在直播但录播启动失败、拿不到直链。
A6. 录播 Cookie 失效。请点击【刷新录播Cookie】打开「抖音Cookie刷新器」，
    按 16.3 节步骤重新采集。若录制「原画」，请确认 cookie.txt 中已包含：
        webcast_local_quality=origin;live_local_quality=origin

Q7. 想录「原画」但一直只录到较低画质。
A7. ① 确认 cookie.txt 有效且包含 origin 画质参数。
    ② 确认「详情/编辑」中录制画质设置正确。
    ③ 在「录播脚本生成器」中若未勾选「优先保证录播完整性」，
       脚本会严格只接受目标画质，可能因链接画质不符而放弃；
       想尽量录到就用「优先保证录播完整性」。
    ④ 部分直播间本身未推原画流，则无法录制原画。

Q8. 录播文件在哪里？为什么是 .flv？
A8. 默认保存在程序所在目录（与主程序同级），扩展名为 .flv。
    若开启了「下播后自动转码」，约 30 秒后会生成 MP4，
    默认放在 %APP_DIR%\已转码\{主播名}\ 下。

Q9. 转码后 MP4 没生成 / FLV 被删了但 MP4 没出现。
A9. ① 确认 ffmpeg.exe 与主程序在同一目录。
    ② 转码脚本有约 30 秒启动延迟，请稍等。
    ③ 查看 TARGET_DIR\converted_files.txt 转码记录。
    ④ 若勾选了「不保留原文件」，转码脚本会先确认 aria2 无该主播活动任务
       再删除；如担心误删，请取消勾选「不保留原文件」。

Q10. 收不到微信通知。
A10. ① 检查三个层面：全局开关是否勾选 → 该主播所属通知组是否启用了
         对应通知方式 → 是否处于「勿扰时段」。
     ② 点【测试通知】验证 AppToken / UID / Webhook 是否正确。
     ③ WxPusher 需要先关注公众号并绑定微信。
     ④ 企业微信 Webhook 需完整复制（含 key= 后面的参数）。

Q11. 自动化任务没有触发。
A11. ① 确认任务的「自启动」为开启状态（可用【切换自启状态】）。
     ② 确认触发条件设置正确（开播用「直播中」，下播用「未开播」）。
     ③ 确认脚本路径仍然有效（文件没被移动或删除）。
     ④ 同名主播跨平台不会误触发，请确认任务绑定的主播与平台正确。
     ⑤ 任务总数上限 20 个，超出后需先删除旧任务。

Q12. 程序占用资源较高 / 电脑很卡。
A12. 到「高级设置」把监控速度档位调高（3~5 档），
     或使用「定时调速」在高峰/深夜自动降档。
     同时减少同时启用监控的主播数量。

Q13. 想换一台电脑使用，怎么迁移？
A13. 拷贝整个程序目录即可。其中关键是：
        · streamer_monitor_config.json （所有设置与主播）
        · cookie*.txt / douyinliveck.txt （Cookie）
        · aria2c.exe / ffmpeg.exe / msedgedriver.exe / aria2.bat 等引擎文件
     新电脑上按第二章重装 Python 依赖，并重新下载与新版 Edge 匹配的
     msedgedriver.exe（版本号必须与新电脑 Edge 一致）。

Q14. 程序关闭时弹出确认框。
A14. 这是安全机制：若检测到仍有活跃的录播任务，程序会提示确认，
     避免误关导致录制中断。确认后程序会停止监控、停止 aria2 并保存配置。

Q15. 如何查看运行日志？
A15. 「日志」标签页可实时查看；磁盘日志位于程序目录 \logs\ 下
     （按天分割时为 monitor-YYYY-MM-DD.log，未分割时为 monitor.log）。
     也可点击【导出日志】或【查看日志文件】。

================================================================================
附录 A  完整配置向导流程（快速上手七步）
================================================================================

 第 1 步：安装 Python 环境，并确保勾选 Add Python to PATH。
 第 2 步：安装依赖。切好国内镜像后执行：
             pip install -r requirement.txt
         或分别安装 requests / selenium / aria2p / psutil。
 第 3 步：准备引擎文件。确认程序目录下已有 aria2c.exe、aria2.bat、
         ffmpeg.exe，并放入与 Edge 版本匹配的 msedgedriver.exe。
 第 4 步：获取录播 Cookie。打开一个【正在直播】的抖音直播间，
         在程序「通知设置 → 刷新录播Cookie」中完成采集，
         并在 cookie.txt 中补上：
             webcast_local_quality=origin;live_local_quality=origin
         提示：只有直播间在直播中但仍拿不到直链时，才需要重新刷新 Cookie。
 第 5 步：获取监控 Cookie。打开主程序后会自动弹出抖音页面采集未登录
         Cookie，等待约 15 秒即可（无图形验证码障碍的情况下）。
 第 6 步：添加要监控的主播。「主播管理」页填写主播名称（可留空）、
         选择平台、填入抖音主页 URL 或 B站 UID、选择通知组，
         点击【添加主播】。当「上次监控时间」开始不断变化，
         说明监控已开始工作。
 第 7 步：建立自动录播任务。
         · 方式一（推荐）：切到「抖音录播(V2)」，把目标主播的
           「自动录播」列点成 ✓，并在「画质」列选好画质即可。
         · 方式二（传统）：用「录播脚本生成器」生成
           「开始录播-{主播名}.py」，再到「自动化任务」页：
               选择主播 → 触发条件选「直播中」→ 浏览选中该脚本
               → 点击【添加任务】→ 最后点【保存配置】。

 完成！此后主播一开播，程序就会自动开始录制，并把 .flv 文件输出到
 程序目录下；若开启自动转码，下播后还会自动生成 MP4。
